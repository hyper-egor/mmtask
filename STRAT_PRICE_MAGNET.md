# PRICE_MAGNET

Спецификация направленной maker-стратегии на краткосрочной инерции цены. Магнитный
уровень можно включать и выключать одним параметром в том же классе стратегии.

Планируемое имя Java-класса: `PriceMagnetStrategy`.

## 1. Цель

Проверить две связанные гипотезы:

1. После движения цены в одну сторону на несколько ticks движение часто продолжается
   еще на небольшую дистанцию.
2. Крупный лимитный объем по направлению движения увеличивает вероятность достижения
   цели и уменьшает неблагоприятное движение до нее.

Стратегия использует пассивные maker-ордера. Это направленная maker/MFT-стратегия, а
не классический постоянно двусторонний market making.

## 2. Два режима одной стратегии

В `PriceMagnetStrategy` должен быть один хорошо видимый переключатель:

```java
private static final boolean USE_MAGNET = true;
```

При `USE_MAGNET = false`:

- вход определяется только инерцией цены;
- target задается фиксированным числом ticks от фактической средней цены входа;
- wall detector на решение не влияет.

При `USE_MAGNET = true`:

- для входа одновременно нужны инерция и подходящая стена по направлению движения;
- target ставится на один tick перед зафиксированной стеной.

Отдельные классы стратегии для этих режимов не создаются. Переключатель и все
параметры должны находиться рядом в начале `PriceMagnetStrategy`, чтобы режим можно
было менять вручную одной строкой.

## 3. Индикатор инерции

Инерция считается отдельным простым классом `PriceInertiaWindow`, похожим по стилю на
`MMATema`.

Внутри хранится `Deque` точек:

```text
timestamp, bestBid, bestAsk
```

На каждом новом snapshot:

1. Новая точка добавляется в конец.
2. Точки старше `inertiaWindowSeconds` удаляются из начала.
3. Текущие цены сравниваются с самой старой оставшейся точкой.

Сигнал разрешен только после достаточного заполнения окна:

```text
currentTimestamp - oldestTimestamp >= inertiaWindowSeconds * minimumWindowCoverageShare
```

Стартовое значение `minimumWindowCoverageShare = 0.75`. Например, для окна 10 секунд
движение за 8 секунд уже может дать сигнал, а за 7 секунд — еще нет.

Расчет:

```text
upMoveTicks = (currentBestAsk - oldestBestAsk) / tickSize
downMoveTicks = (oldestBestBid - currentBestBid) / tickSize
```

Сигнал:

```text
если upMoveTicks >= minimumMoveTicks: UP
иначе если downMoveTicks >= minimumMoveTicks: DOWN
иначе: FLAT
```

Если одновременно выполнены UP и DOWN, выбирается движение с большим числом ticks.
При равенстве возвращается `FLAT`.

Один snapshot добавляется в окно ровно один раз. Первый snapshot после очистки окна
не создает сигнал. При повторном replay с более раннего timestamp окно очищается.

## 4. Магнитный уровень

Стена отслеживается по фиксированной цене, а не по номеру уровня в стакане.

Уровень считается подходящей стеной, если:

- объем не меньше `minimumWallVolume`;
- объем не меньше `wallRatio` медианы объемов TOP20 той же стороны;
- уровень существует не меньше `minimumWallAgeSeconds`;
- доля времени присутствия не меньше `minimumPresenceShare`;
- краткий пропуск не длиннее `wallMissingGraceSeconds` не начинает новый эпизод;
- текущий объем не меньше `minimumRetainedVolumeShare` от объема при подтверждении;
- расстояние от соответствующего touch находится в диапазоне
  `minimumWallDistanceTicks..maximumWallDistanceTicks`;
- суммарный объем между touch и стеной не больше `maximumThinVolumeRatio` от объема
  стены.

Используются только текущий и прошлые snapshots. Если подходящих стен несколько,
выбирается ближайшая по направлению движения.

Соответствие направления и стены:

```text
UP   → ask-wall выше текущего best ask
DOWN → bid-wall ниже текущего best bid
```

## 5. Торговый план

При появлении нового сигнала стратегия фиксирует один торговый план:

```text
direction
signalTime
entryOrderPrice
source: INERTIA или MAGNET
wallPrice и targetPrice для MAGNET
```

План не заменяется более новой возможностью того же направления. Одновременно может
существовать только один торговый цикл. Накопление нескольких независимых входов и
пирамидинг в первой версии запрещены.

Один непрерывный сигнал создает не более одного входа. Новый вход того же направления
разрешается только после того, как сигнал сначала стал `FLAT` или противоположным.

## 6. Ордер входа

При нулевой позиции и отсутствии незавершенного цикла:

```text
UP   → BUY по текущему best bid
DOWN → SELL по текущему best ask
```

В режиме магнита вход разрешен только при наличии соответствующей стены.

Цена входного ордера фиксируется при создании плана. Незначительные изменения best
price не вызывают replacement: существующий ордер получает `KEEP`.

Неисполненный вход отменяется, если:

- появился противоположный сигнал;
- прошло `entryTimeoutSeconds`;
- стакан стал stale или возник gap;
- ордер запрещен общей hard-limit logic.

Сигнал `FLAT` сам по себе не отменяет уже выставленный вход. Пассивный ордер остается
на зафиксированной цене до timeout или другой явной причины отмены: иначе краткая
пауза инерции снимает ордер именно тогда, когда цена возвращается к нему и может дать
fill.

В режиме магнита стена проверяется только в момент создания торгового плана. После
этого `wallPrice` и `targetPrice` зафиксированы: исчезновение, уменьшение или удаление
стены из видимой части стакана не отменяет ожидающий вход и не меняет target. Стена
здесь является исходным сигналом, а не условием сопровождения уже созданного плана.

После первого partial или полного fill остаток входного ордера отправляется на
отмену. Стратегия управляет только фактически полученной позицией. Из-за latency до
активации cancel возможны дополнительные fills; они учитываются через фактические
inventory и average entry price.

## 7. Обычный выход

Выходной ордер всегда только уменьшает позицию и не может перевернуть ее.

### Режим без магнита

Target считается от фактической средней цены позиции:

```text
long:  targetPrice = averageEntryPrice + fixedExitTicks * tickSize
short: targetPrice = averageEntryPrice - fixedExitTicks * tickSize
```

Если из-за дополнительных fills во время cancel изменилась `averageEntryPrice`,
target пересчитывается от новой средней цены.

### Режим с магнитом

Target фиксируется в торговом плане:

```text
UP + ask-wall:   targetPrice = wallPrice - tickSize
DOWN + bid-wall: targetPrice = wallPrice + tickSize
```

Target не двигается вслед за стеной. Если стена уменьшилась или исчезла уже после
fill входа, target сохраняется: event study показал, что цена часто достигает
зафиксированного уровня после исчезновения стены.

### Общие правила выхода

- long закрывается `SELL`, short закрывается `BUY`;
- размер exit-ордера равен модулю фактического inventory;
- target-ордер не следует за best price и получает `KEEP`;
- partial exit уменьшает inventory, остаток продолжает закрывать позицию;
- при изменении фактического inventory размер выхода приводится к остатку позиции;
- при `inventory = 0` все ордера цикла отменяются, цикл считается завершенным.

Если рынок уже прошел target до выставления ордера, используется текущий лучший
пассивный price, который дает не худший результат:

```text
long:  exitOrderPrice = max(targetPrice, bestAsk)
short: exitOrderPrice = min(targetPrice, bestBid)
```

Это не позволяет заведомо marketable-ордеру быть отклоненным существующей fill
model.

## 8. Комиссии

Комиссия применяется существующим portfolio accounting к каждому фактическому fill и
входит в realized, unrealized и итоговый net PnL.

Стратегия намеренно не проверяет перед входом, покрывает ли расстояние до target
spread, комиссии или дополнительный safety margin. Комиссия не изменяет сигнал,
target и правила выставления ордеров.

Эксперимент запускается вручную с разными значениями `makerFeeBps`, включая `0`, а
влияние комиссии оценивается по финальным отчетам.

## 9. Реверс

Реверсом считается противоположный сигнал самого индикатора инерции. В режиме
магнита новая стена не нужна, чтобы начать защищать уже открытую позицию; она
потребуется только для последующего входа в обратную сторону.

Если при открытой позиции появился такой сигнал:

1. Дальний target отменяется.
2. Стратегия переходит в режим `RISK_EXIT` и закрывает текущую позицию по лучшей
   пассивной цене.
3. До фактического `inventory = 0` новая позиция не открывается.
4. После выхода, если противоположный сигнал все еще действует и удовлетворяет
   правилам текущего режима, создается новый торговый план.
5. После нового fill выставляется новый target.

Прямой flip одним ордером размером `abs(inventory) + orderSize` не используется. Это
избегает неоднозначности при partial fills и cancel latency.

## 10. Досрочный выход и risk-off

Стратегия отказывается ждать target и переходит в `RISK_EXIT`, если:

- возник противоположный сигнал;
- цена ушла против средней цены позиции на `stopLossTicks`;
- позиция удерживается дольше `maximumHoldingSeconds`;
- дальнейшее сохранение ордеров запрещено общей risk logic;
- после gap или stale-периода обнаружена незакрытая позиция.

`FLAT` после уже состоявшегося входа не является причиной немедленного закрытия:
нейтральные колебания индикатора не должны создавать лишний churn.

Stop-loss проверяется по доступной цене закрытия:

```text
long:  bestBid <= averageEntryPrice - stopLossTicks * tickSize
short: bestAsk >= averageEntryPrice + stopLossTicks * tickSize
```

Время удержания отсчитывается от первого fill входа.

В `RISK_EXIT`:

- long закрывается `SELL` по best ask;
- short закрывается `BUY` по best bid;
- ордер может следовать за best price, но replacement разрешен не чаще одного раза за
  `riskExitRefreshMillis`;
- после перехода в `RISK_EXIT` стратегия не возвращается к старому target и продолжает
  закрытие до нулевого inventory.

Это пассивный maker-exit, поэтому немедленное исполнение не гарантируется. Taker
исполнение, market order, taker fee и slippage в этой стратегии не моделируются.

## 11. Состояния стратегии

Используется небольшой явный автомат:

| Состояние | Смысл |
|---|---|
| `FLAT` | Позиции и торгового плана нет, ожидается новый сигнал |
| `ENTRY_PENDING` | Фиксированный вход ожидает fill |
| `POSITION_OPEN` | Позиция открыта, стоит обычный target |
| `RISK_EXIT` | Обычный target отменен, позиция закрывается по best price |

Переход определяется фактическим inventory и состоянием active/pending orders, а не
предположением, что cancel уже исполнился. При cancel latency старый ордер остается в
worst-case position range до фактического применения команды.

На каждой стороне одновременно допускается не больше одного ордера. Exit имеет
приоритет над новым entry.

## 12. Inventory, fills и gaps

- Начальный размер входа — `orderSize`.
- Hard inventory limit и projected-order проверки наследуются от общего backtest.
- Новые входы при ненулевом inventory запрещены, кроме продолжения уже начавшегося
  partial fill до применения cancel.
- Все fills подтверждаются существующей trade-based queue model.
- Touch цены сам по себе не считается fill.
- При gap active и pending orders очищаются общей backtest-механикой.
- Inventory, PnL и average entry price при gap сохраняются.
- После первого свежего snapshot незакрытая позиция переводится в `RISK_EXIT`.
- Индикатор инерции после gap начинает накапливать новое окно и не использует старую
  цену как начало движения.

## 13. Параметры первого запуска

Все параметры находятся рядом в одном понятном месте. Значения являются стартовыми,
а не результатом оптимизации.

| Параметр | Стартовое значение | Смысл |
|---|---:|---|
| `useMagnet` | `true` | Включить wall-фильтр и wall-target |
| `inertiaWindowSeconds` | `3` | Окно оценки движения цены |
| `minimumMoveTicks` | `2` | Минимальное движение для UP/DOWN |
| `minimumWindowCoverageShare` | `0.75` | Минимальная заполненность окна перед сигналом |
| `fixedExitTicks` | `3` | Target без магнита от average entry price |
| `entryTimeoutSeconds` | `3` | Максимальное ожидание fill входа |
| `maximumHoldingSeconds` | `60` | Максимальное время открытой позиции |
| `stopLossTicks` | `6` | Переход в risk-exit при движении против позиции |
| `riskExitRefreshMillis` | `250` | Минимальный интервал replacement risk-exit |
| `orderSize` | `1 ETH` | Размер входного ордера |
| `hardInventoryLimit` | `5 ETH` | Общий hard limit backtest |
| `wallRatio` | `3.0` | Объем стены относительно медианы TOP20 |
| `minimumWallVolume` | `3 ETH` | Минимальный абсолютный объем стены |
| `minimumWallAgeSeconds` | `3` | Минимальный возраст стены |
| `minimumPresenceShare` | `0.80` | Минимальная доля времени присутствия |
| `presenceCreditCapMillis` | `250` | Максимальный зачет одного интервала snapshots в присутствие |
| `minimumRetainedVolumeShare` | `0.50` | Остаток объема после подтверждения |
| `wallMissingGraceSeconds` | `0.50` | Допустимый краткий пропуск стены |
| `minimumWallDistanceTicks` | `1` | Минимальное расстояние до стены |
| `maximumWallDistanceTicks` | `7` | Максимальное расстояние до стены |
| `maximumThinVolumeRatio` | `0.50` | Максимальный объем перед стеной относительно нее |

`makerFeeBps`, latency и stale threshold остаются общими параметрами backtest, а не
частью торгового сигнала.

## 14. Минимальная структура Java-кода

Не нужен универсальный signal framework. Достаточно:

- `PriceMagnetStrategy` — состояния, торговый план и решения по ордерам;
- `PriceInertiaWindow` — окно цен и классификация `UP / DOWN / FLAT`;
- небольшой внутренний `TradePlan` — зафиксированные direction, entry и target;
- простая wall-state логика внутри стратегии либо один небольшой `PriceWallDetector`,
  если код стены начинает мешать чтению автомата.

Логика выбора режима должна находиться в одном коротком месте:

```text
если USE_MAGNET:
    требовать подходящую стену
    target брать перед стеной
иначе:
    использовать только инерцию
    target считать через fixedExitTicks
```

Не дублировать order lifecycle, risk-exit и inventory logic для двух режимов.

## 15. Метрики и сравнение

Оба режима прогоняются отдельно на одних данных и с одинаковой fill model.

Сравниваются:

- total и daily net PnL;
- realized и unrealized PnL;
- комиссии;
- число entry fills и завершенных циклов;
- доля закрытий обычным target и через `RISK_EXIT`;
- среднее и максимальное время удержания;
- средний и максимальный inventory;
- max drawdown;
- adverse excursion после entry;
- число replacements, особенно в `RISK_EXIT`;
- результаты отдельно для UP/DOWN и по дням.

Основные сравнения:

1. `USE_MAGNET = false` против `USE_MAGNET = true` при `makerFeeBps = 0`.
2. Те же режимы при выбранных ненулевых комиссиях.

Комиссионный прогон используется для оценки результата, но не меняет правила самой
стратегии.

## 16. Проверки перед полным replay

Нужны небольшие синтетические сценарии:

- UP и DOWN по ценам в окне инерции;
- отсутствие сигнала при недостаточном движении;
- вход по best price и `KEEP` при небольшом движении рынка;
- отмена входа по timeout, FLAT, reverse и исчезновению стены;
- target от average entry в режиме без магнита;
- target на один tick перед стеной в режиме магнита;
- исчезновение стены после fill не меняет target;
- partial entry вызывает cancel остатка;
- partial exit не переворачивает inventory;
- reverse сначала закрывает позицию и только потом разрешает новый вход;
- stop-loss и maximum holding переводят стратегию в `RISK_EXIT`;
- refresh risk-exit не происходит чаще заданного интервала;
- gap очищает индикатор и после восстановления переводит позицию в `RISK_EXIT`;
- hard inventory limit не нарушается с учетом pending cancel/place.

## 17. Основание гипотезы и ограничения

Последний Python event study при окне 3 секунды и движении минимум 2 ticks дал:

- `WALL`: 85.6% достижения цели;
- `YOUNG_LEVEL`: 84.0%;
- `NO_WALL`: 78.5%;
- `WALL - NO_WALL`: `+7.1 п.п.`;
- при стене цель достигалась быстрее, а движение в неблагоприятную сторону было
  меньше.

Это подтверждает ценовую гипотезу, но не торговую прибыльность. Высокий hit rate не
учитывает вероятность fill входа, очередь, порядок entry/target fills и комиссии.
Java backtest должен проверить именно эти ограничения.

Три дня остаются маленькой in-sample выборкой. Параметры нельзя считать устойчиво
оптимальными, даже если один из прогонов показывает хороший PnL.

Заполняется после реализации и replay обоих режимов. Здесь фиксируются параметры,
ссылки на CSV/графики, различия результатов и решение: оставить механику магнита,
оставить только инерцию либо отвергнуть весь вариант.
