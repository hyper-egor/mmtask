# Price Magnet / Price Inertia

Java-класс: `PriceMagnetStrategy`.

## 1. Гипотеза

После краткосрочного направленного движения цена может продолжить движение к
крупному устойчивому уровню ликвидности. Такой уровень рассматривается не как
поддержка или сопротивление, а как «магнит»: область повышенной вероятности контакта,
которую можно использовать как цель пассивного торгового цикла.

Гипотеза интересна тем, что разделяет два вопроса:

1. действительно ли цена чаще достигает уровня;
2. можно ли получить maker fill на входе и затем закрыть позицию с прибылью.

Высокий hit rate в первом вопросе не гарантирует положительный PnL во втором.

## 2. Два режима реализации

Класс поддерживает два варианта через `USE_MAGNET`:

- `true` — инерция создает направление, а подтвержденная wall задает target;
- `false` — контрольный вариант использует только price inertia.

В текущем коде `USE_MAGNET = false`. Поэтому сохраненный Java-run
`results/PriceMagnetStrategy` относится к **inertia-only control**, несмотря на имя
класса. Магнитный эффект отдельно проверен Python event study.

## 3. Сигнал инерции

В окне 5 секунд хранятся best bid/ask. После заполнения минимум 75% окна сравниваются
текущая и самая старая mid price:

- рост минимум на 2 ticks — `UP`;
- падение минимум на 2 ticks — `DOWN`;
- иначе — `FLAT`.

Будущие данные в сигнале не используются.

## 4. Wall detector

При `USE_MAGNET = true` впереди движения ищется ближайший устойчивый крупный уровень.
Текущие параметры кода:

| Параметр | Значение |
|---|---:|
| Размер относительно соседних уровней | 2.0 |
| Минимальный объем | 2 ETH |
| Минимальный возраст | 2 с |
| Минимальная доля присутствия | 80% |
| Сохраняемая доля исходного объема | 50% |
| Grace после исчезновения | 0.5 с |
| Расстояние от touch | 2–12 ticks |
| Максимальная промежуточная ликвидность | 90% объема wall |

Для движения вверх target находится на tick перед ask-wall; для движения вниз — на
tick перед bid-wall. После создания trade plan wall повторно не проверяется: target
фиксируется, даже если видимый объем исчез.

## 5. Торговый цикл

Стратегия хранит четыре состояния: `FLAT`, `ENTRY_PENDING`, `POSITION_OPEN` и
`RISK_EXIT`.

### Вход

- `UP` создает maker buy по best bid, `DOWN` — maker sell по best ask.
- Размер входа наследуется из `BacktestParameters`.
- На один непрерывный сигнал разрешен один торговый план; новый цикл требует `FLAT`
  или смены направления.
- Пока сигнал сохраняется, entry может следовать за best только по направлению
  импульса; target сдвигается на ту же величину.
- Entry отменяется при противоположном сигнале или через 1 секунду без fill.
- Cancel barrier не позволяет открыть новый цикл до завершения cancel latency.

### Выход

После первого fill остаток входного ордера сначала отменяется. Затем выставляется
лимитный ордер на весь фактический inventory:

- в magnet-режиме — по зафиксированному wall target;
- в inertia-only режиме — по target на 1000 ticks от average entry.

Значение 1000 ticks практически отключает обычный profit target в контрольном
inertia-only запуске. Аналогично stop-loss равен 1000 ticks. Фактический защитный
выход обычно запускается maximum holding time 10 секунд или противоположным сигналом.

В `RISK_EXIT` позиция сокращается лимитным ордером по текущему touch. Цена может
обновляться не чаще одного раза в 250 мс. Ордер не может перевернуть inventory.

### Gaps и risk

- Stale book очищает краткосрочные индикаторы и биржевые ордера.
- Если inventory открыт, после восстановления стратегия переходит в `RISK_EXIT`.
- Hard inventory limit учитывает active и pending orders.
- Taker execution не моделируется: даже risk exit остается maker-ордером.

## 6. Event study магнитного эффекта

Исследование 1521 wall event показало:

- target hit rate для `WALL`: 88.0%;
- для `NO_WALL`: 81.1%;
- разница: `+6.9 п.п.`;
- приблизительный 95% интервал разницы: `[+4.3; +9.5] п.п.`;
- wall была снята во время наблюдения в 52.3% случаев.

Это поддерживает ценовую гипотезу, но не доказывает торговую исполнимость. Цена могла
достичь target без fill нашего maker-входа. Подробности:
[scripts/price_magnet/FINDINGS.md](scripts/price_magnet/FINDINGS.md).

## 7. Сохраненный Java-run

Текущий артефакт получен при `USE_MAGNET = false`, maker fee 0 bps, order size 1 ETH
и hard limit 5 ETH:

| Период | Daily net PnL, USD | Fill volume, ETH |
|---|---:|---:|
| 2026-03-19 | -11.23 | 30.750 |
| 2026-03-20 | -6.47 | 22.432 |
| 2026-03-21 | +2.19 | 8.846 |
| **Всего** | **-15.51** | **62.028** |

Max drawdown составил 26.54 USD, финальный inventory — 0 ETH.

Этот результат отвергает текущую inertia-only торговую механику. Он не является
чистым PnL-тестом `USE_MAGNET = true`; для такого сравнения необходимо сохранить
отдельный run с флагом и параметрами в отчете.

## 8. Вывод и ограничения

Price Magnet остается содержательной исследовательской идеей: event study показывает
измеримый эффект достижения уровня. Но текущие данные не подтверждают, что этот
эффект превращается в устойчивый maker edge.

Основные ограничения:

- только три in-sample дня;
- wall events внутри одного режима могут быть зависимы;
- wall может исчезнуть или быть результатом spoofing;
- достижение цены не гарантирует maker fill входа;
- текущий Java-result относится к контрольному режиму без wall target;
- комиссия в сохраненном Java-run равна нулю.

Поэтому стратегия не вошла в финальный вариант, но полезна как пример того, почему
предиктивный сигнал нужно отдельно проверять через execution model.
