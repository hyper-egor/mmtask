# PRICE_WALLS: первый event study

## Параметры

- `wallRatio = 2.0`
- `minimumWallVolume = 10.0 ETH`
- `minimumWallAgeSeconds = 10.0`
- `minimumPresenceShare = 0.8`
- `entryDistanceTicks = 3`
- `maximumThinVolumeRatio = 0.25`
- `missingGraceSeconds = 0.5`

## Объем выборки

- Подтвержденных wall events: **1109**.
- Сопоставленных control events: **1109**.

Событий достаточно для первого сравнения, но три дня остаются малой in-sample выборкой. Решение нужно принимать по стабильности между днями и по отличию от controls, а не только по общему среднему.

## Предварительное чтение результата

В стартовой конфигурации средний направленный mid move после wall-сигнала отрицателен для BID через 5с (-1.748 ticks) и 30с (-2.800 ticks), а также для ASK через 5с (-1.630 ticks) и 30с (-2.978 ticks). Это не подтверждает простой тезис, что persistence сама по себе дает средний отскок. First-passage для BID выглядит лучше: bounce был первым в 29.3% случаев против break в 63.0%. Для ASK bounce был первым в 30.4%, break — в 61.6%. Результат смешанный и пока не дает основания переносить стратегию в Java.

На самый насыщенный день приходится 37.6% wall events. Поэтому общий итог нельзя интерпретировать без дневного разреза.

Положительный `entryMarkout` сам по себе не является доказательством edge: виртуальный
ордер мог не получить fill. Реальный fill возникает именно при движении цены к стене,
поэтому следующий backtest обязан применять trade-based queue model.

## Ограничения интерпретации

- Это event study, а не backtest PnL.
- Controls проверяют пользу persistence относительно молодых крупных уровней, но не
  являются идеальной случайной выборкой всех обычных уровней.
- События одной и той же рыночной фазы могут быть зависимы.
- Три дня нельзя использовать для массового подбора порогов.
