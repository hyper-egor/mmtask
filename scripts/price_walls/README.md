# Исследование PRICE_WALLS

## Зачем нужен скрипт

`analyze_price_walls.py` проверяет исследовательскую гипотезу до изменения Java
backtest.

Главный вопрос: после приближения цены к крупному устойчивому объему рынок чаще
отскакивает от него или пробивает его?

Это не backtest стратегии. Скрипт не моделирует очередь, latency, fills, inventory и
PnL. Он проверяет только наличие краткосрочного ценового эффекта. Если эффекта нет,
добавлять новую стратегию в Java не нужно.

## Как работает детектор

Скрипт последовательно читает все snapshots трех дней. Решение в текущей строке
использует только текущий и предыдущие snapshots.

Для каждого snapshot и каждой стороны стакана:

1. Считается медианный объем TOP20.
2. Уровни с объемом не меньше `MIN_WALL_VOLUME` и отношением к медиане не меньше
   `WALL_RATIO` становятся кандидатами.
3. Кандидат отслеживается по точной цене. Переход цены с одного номера уровня на
   другой не создает новую стену.
4. Непрерывность допускает короткие пропуски не длиннее `MISSING_GRACE_SECONDS`.
5. Время присутствия накапливается по реальному времени между snapshots. Большое
   число частых snapshots само по себе не увеличивает возраст стены.
6. Кандидат подтверждается только после `MIN_WALL_AGE_SECONDS` и достижения
   `MIN_PRESENCE_SHARE`.
7. После подтверждения событие создается, когда стена находится на расстоянии от 1
   до `ENTRY_DISTANCE_TICKS`, а объем перед ней не превышает
   `MAX_THIN_VOLUME_RATIO` от объема стены.
8. Для одного непрерывного эпизода стены создается не более одного события.

Для bid-стены виртуальная цена ордера равна `wall price + 1 tick`. Для ask-стены —
`wall price - 1 tick`. Скрипт не утверждает, что этот ордер получил fill.

## Защита от look-ahead

- Стена не считается известной до окончания минимального возраста.
- Будущие snapshots не участвуют в создании события.
- Будущая цена используется только после фиксации события для расчета результата.
- Данные каждого дня обрабатываются отдельно. Состояние стены не переносится через
  границу дня или gap больше одной секунды.

## Что измеряется после события

- движение mid-price в сторону ожидаемого отскока через 1, 5, 10, 30 и 60 секунд;
- markout виртуальной цены ордера на тех же горизонтах;
- максимальное благоприятное и неблагоприятное движение за 60 секунд;
- что произошло раньше: отскок на два ticks или пробой стены;
- сколько времени стена оставалась видимой после сигнала;
- исчезла ли стена до касания виртуальной цены ордера.

Знак всех направленных метрик одинаков:

- положительное значение благоприятно для предполагаемого ордера;
- отрицательное значение означает движение против него.

## Контрольная группа

В качестве простой контрольной группы используются крупные уровни с теми же
условиями расстояния и тонкости, но еще не достигшие минимального возраста стены.

Такое сравнение отвечает на узкий вопрос: добавляет ли именно persistence пользу к
самому факту крупного объема. Контроль фиксируется online; скрипт не проверяет
задним числом, станет ли этот уровень устойчивой стеной позднее.

Число control events ограничивается числом wall events отдельно по дню и стороне.
Отбор детерминированный, чтобы повторный запуск давал тот же результат.

## Файлы результата

- `events.csv` — все подтвержденные wall events и их будущие результаты;
- `controls.csv` — сопоставимая контрольная выборка;
- `summary.csv` — агрегаты по дням, сторонам и типам событий;
- `FINDINGS.md` — короткий автоматически сформированный отчет;
- `volume_distribution.csv` — распределение объемов уровней для проверки абсолютного
  порога.

## Стартовые настройки

Настройки находятся в начале скрипта:

```text
WALL_RATIO = 5.0
MIN_WALL_VOLUME = 10.0 ETH
MIN_WALL_AGE_SECONDS = 10
MIN_PRESENCE_SHARE = 0.80
ENTRY_DISTANCE_TICKS = 3
MAX_THIN_VOLUME_RATIO = 0.25
MISSING_GRACE_SECONDS = 0.50
OUTCOME_WINDOW_SECONDS = 60
```

Это первая диагностическая точка, а не результат оптимизации. Если событий окажется
слишком мало, сначала изучается `volume_distribution.csv`, после чего допускается
одна небольшая проверка чувствительности. Массовый перебор параметров на трех днях не
проводится.

## Запуск

Из корня проекта:

```bash
python scripts/price_walls/analyze_price_walls.py
```
